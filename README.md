# サッシ呼称チェッカー

サッシの呼称（例：`16520`）を入力するだけで、そのサイズが実在するかを確認できるツールです。
YKK AP APW430 / APW330（APW330カタログ掲載のAPW 411通風ドアを含む）と LIXIL TW（それぞれ通常・防火）に対応しています。

**公開URL：https://harutong08.github.io/sash-code-checker/**

Claudeアカウントなど一切不要、リンクを開くだけで誰でも使えます。


## 使い方

### 1. メーカーと区分を選ぶ

- メーカー：YKK AP APW430 / APW330 ／ LIXIL TW
- 区分：通常サッシ ／ 防火サッシ

同じ呼称でも、メーカー・区分が違うと結果も変わります。

APW430とAPW330のように同じメーカー内に複数シリーズがある場合は、「シリーズで絞り込む」プルダウンで
どちらかに絞り込めます（絞り込まなければ両方まとめて表示されます）。

### 2. 呼称で調べる

「サッシ呼称」欄に番号を入力するだけです。

- 例：`16520`
- 例：`F16520`（頭に記号を付けると窓種を絞り込めます）

| 記号 | 窓種 |
|---|---|
| F | FIX窓 |
| S | すべり出し窓 |
| T | たてすべり出し窓 |
| AW | 引違い窓 |
| TF / SF | FIXとの組み合わせ（段窓） |
| TR / SR | FIXとの横並び（連窓。2連・3連とも） |
| TFT / SFS | 3連窓だけに絞る（たてすべり出し＋FIX＋たてすべり出し／すべり出し＋FIX＋すべり出し） |

※LIXIL TWでは `T`＝縦すべり出し窓、`TR`＝縦すべり出し窓＋FIX連窓（2連・3連）、`TFT`＝縦すべり出し窓の3連窓です。

※`T+F+T16507` のように `+` で区切って書いても `TFT16507` と同じに扱います。

※連窓は「2連窓」（可動＋FIX）と「3連窓」（可動＋FIX＋可動。YKKのたてすべり出し窓はウインドウキャッチ連窓）に
　分けて表示します。`16007` のように**同じ呼称が2連窓と3連窓の両方にある**場合は、両方の結果が出ます
　（2連窓は障子W060、3連窓は障子W036の組み合わせ）。
　対象：たてすべり出し窓・すべり出し窓・ツーアクション窓・開き窓テラス（APW430）・外倒し窓・片上げ下げ窓（APW330）・
　縦すべり出し窓（LIXIL TW）。段窓（上が可動・下がFIX）は「〜＋FIX段窓」として別の窓種にしています。

※記号を付けなくても検索できます。

※LIXIL TWの一部の呼称には、末尾に `M`（マドタイプ）・`A`／`B`（2×4など段差違い）が付きます。
　例：`02118M`、`03618A` のように、末尾のアルファベットも含めてそのまま入力してください。

### 3. 番号が分からないときは選ぶだけでもOK

「または、サイズから選ぶ」で、幅→高さをプルダウンで選べば呼称が分かります。
（実寸(mm)でも呼称でも選べます）

### 4. 複数まとめて調べたいとき

「まとめてチェック」タブへ。図面の呼称一覧をそのまま貼り付けて「まとめて判定」を押すだけです。

### 5. 結果の見方

- カード左の図：斜め線＝開き方、色付きの縁＝通常（緑）／防火（赤）
- 「あり」→ その規格は実在します（窓種・サイズ・カタログ頁つき）
- 「なし」→ 存在しません（似た番号があれば候補を出します）

- 「カタログ P.xx 掲載」の `P.xx` はリンクになっており、クリックするとメーカー公式のWEBカタログが
  該当ページを開いた状態で別タブに表示されます（仕組みは後述の「カタログの直接ページリンクの仕組み」を参照）。

### 困ったときは

画面下の「呼称の読み方」に、番号の仕組みと出典カタログが書いてあります。
**最終確認は必ずカタログ本紙で行ってください。**


## アプリとしてインストールする

このサイトはPWA（インストール可能なWebアプリ）として作られています。

| 環境 | 手順 |
|---|---|
| Windows（Chrome/Edge） | サイトを開く → アドレスバー右側の「インストール」アイコン、または「…」メニュー→アプリ→このサイトをインストール |
| Android（Chrome） | サイトを開く → 「ホーム画面に追加」／「アプリをインストール」 |
| iPhone（Safari） | サイトを開く → 共有ボタン → 「ホーム画面に追加」 |

インストール後もアイコンをタップするたびに最新版を読みに行くので、**更新のたびに入れ直す必要はありません**。


## 技術構成

- 単一の `index.html`（HTML/CSS/JSと全データを内包した自己完結ファイル。判定処理自体は外部通信なしで動く。
  カタログ頁番号のリンクだけは、クリックすると利用者の操作でメーカー公式サイトへ移動する）
- `manifest.json`：アプリ名・アイコン・単独ウィンドウ表示の設定
- `sw.js`：サービスワーカー。オンライン時は常に最新を取得し、オフライン時のみキャッシュにフォールバック
- `icons/`：アプリアイコン（192px・512px）
- ホスティング：GitHub Pages（`main`ブランチのルートを配信）

データはYKK AP・LIXILの各商品カタログのページを直接確認しながら手作業で登録しています
（掲載頁はカード内に表示、出典はページ下部の「呼称の読み方」を参照）。


## カタログの直接ページリンクの仕組み

結果カードの「P.xx」のリンク先は、`index.html` 内 `ykkPageUrl()` / `lixilPageUrl()` で
組み立てています。

両社とも、ページ指定は**表紙から数えた通し番号**で受け取ります。表紙（H1／表1）と表2の
2ページが掲載頁1の前に入るため、**通し番号 = 掲載頁 + 2** です（`catalogSheetNo()`）。
この番号さえ渡せば、見開きID（`pageGroupId`）と左右どちらのページか（`pagePosition`。
スマホの単ページ表示で効く）はメーカー側が計算してくれます。

- **YKK AP**：`oc.do?c=<カタログコード>&p=<通し番号>&v=YKKAPDC1&d=pro`
  （カタログコードは `YKK_CATALOG_CODES` でシリーズごとに固定）
- **LIXIL TW**：`openCatalogAuth.cgi?c=SN3600&p=<通し番号>`
  （`SN3600` はTW・TW防火戸共通のカタログコード）

⚠️ **掲載頁番号をそのまま渡してはいけません。** 見開き単位のIDとして解釈され、実際の倍近く先の
ページが開きます（YKKで一度これをやって「たまに違うページが開く」不具合になった）。
両社のページ一覧API（`webapi.do?api=getCatalogpageInfo`）が返す `pid`／`groupid`／`number` で
対応関係を検証済みで、アプリが生成する全リンクが正しい掲載頁を開くことも
実際にリダイレクトを追跡して確認しています。

### 対象カタログ（2026年9月時点の現行版）

| シリーズ | カタログ | コード |
|---|---|---|
| APW430系 | APW 430／430防火窓 商品カタログ（164頁） | `XAAAA-H26-074-2` |
| APW330系 | APW 330／330防火窓 商品カタログ（188頁） | `XAAAA-H26-072-2` |
| LIXIL TW | TW・TW防火戸 商品カタログ（448頁） | `SN3600` |

YKKは以前「一般2冊＋防火1冊」でしたが、現行版では**シリーズごとに一般と防火が1冊に統合**され、
単窓・連窓・段窓のサイズ表も1ページにまとまりました。そのため旧版とは頁番号が全く異なります。
データの掲載頁は、各呼称コードをカタログの全文検索APIにかけ、目次の章範囲と
サイズ表の左上バッジ（「APW 330」／「APW 330 防火窓」）で照合して現行版に更新しています。

もしメーカー側の仕様変更で状況が変わった場合や、特定のページだけ個別URLを見つけた場合は、
`PAGE_URL_OVERRIDES` にそのページだけの個別URLを追記すれば上書きできます。

```js
const PAGE_URL_OVERRIDES = {
  'APW430-70': 'https://webcatalog.ykkap.co.jp/.....（該当ページの個別URL）',
};
```

- キーは `` `${カタログ区分}-${カード内の掲載頁番号}` ``
- カタログ区分は次の3種類（カード内のシリーズ表記から判断。一般・防火は同じ区分）
  - `APW430`：APW 430／431（防火窓を含む）
  - `APW330`：APW 330／331（防火窓を含む）、APW 411（通風ドア。APW330のカタログに掲載）
  - `TW`：LIXIL TW／TW防火戸


## 更新のしかた

1. `index.html` を編集する
2. コミットして `main` ブランチへ push する
3. 数十秒〜1分ほどでGitHub Pagesに自動反映される（`manifest.json` や `icons/` を変えたときも同様）

公開URL・インストール済みアプリのショートカットは変わらないため、利用者側の操作は不要です。


## カタログとの定期照合（`tools/catalog_audit/`）

データの登録漏れやメーカーの改版を見逃さないための点検スクリプトです。毎月1回、ルーティンで自動実行しています。

```bash
sudo apt install tesseract-ocr && pip install pytesseract pillow
python3 tools/catalog_audit/audit.py             # 新版チェック＋全ページ照合（10分程度）
python3 tools/catalog_audit/audit.py --skip-ocr  # 新版チェックだけ（数秒）
```

1. **新版チェック**：各社のカタログ検索APIで、今リンクしているカタログより後に登録された同名カタログ
   （APW 430／APW 330／TW・TW防火戸の商品カタログ）がないかを調べます。
2. **ページ照合**：サイズ表のページ画像をOCRして呼称を拾い、`index.html` のデータ（掲載頁ごと）と比べます。
   - 「カタログにあってデータにない」＝登録漏れ、または掲載頁のズレ
   - 「データにあってこのページにない」＝掲載頁のズレ、またはOCRの読み落とし
3. 目視でOCRノイズと確認済みの差分は `baseline.json` に記録してあり、レポートからは除かれます。
   結果は `tools/catalog_audit/report.md` に出ます。

OCRは読み違えることがあるので、差分が出たら**必ずページ画像で確認してからデータを直す**こと。
確認してノイズだったものは `--update-baseline` で記録します（本物の登録漏れを baseline に入れないこと）。
